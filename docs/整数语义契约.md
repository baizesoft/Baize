# 白泽整数语义契约

> [!info] 为什么有这份文档
> `原生后端验收.md` 原写"溢出、除零和最小整数除以 -1 的统一行为待定义"。本文基于**本机真实编译运行**把这些边界定死，兑现项目"先定义契约和验收标准再编码"的原则（`README.md` 项目原则）。所有结论为 A 档实测，非推测。
>
> **2026-11-21 双平台实测完成**：Windows x86-64（PowerShell 真机）与 Linux x86-64（WSL Ubuntu，用可信根重建的 stage3 编译器）四情形全部一致。底层同为 x86-64 `idiv`，语义相同；仅崩溃的**失败码表现形式**因 OS 而异（见下表）。

## 整数基本约定

- 原生整数为**有符号 64 位**（`int64`，范围 `-9223372036854775808` ~ `9223372036854775807`）。
- 字面量按源码字节解析；不支持浮点。
- 数学结果可表示时，除法**向零截断**。

## 四种边界的确切行为

| 情形 | 约定行为 | 底层机制 | Windows x86-64 实测 | Linux x86-64 实测（WSL stage3） |
| :--- | :--- | :--- | :--- | :--- |
| 除法除不尽 | 向零截断，负数不向下取整 | `cqo` + `idiv` | `-7 / 3 = -2`；`7 / -3 = -2`；RUN_RC=0 | `-7 / 3 = -2`；`7 / -3 = -2`；RUN_RC=0 |
| 除以零 | **运行时失败**：CPU 除零异常，进程非零退出，无输出 | `idiv` 触发 `#DE` | 退出码 `0xC0000094` (STATUS_INTEGER_DIVIDE_BY_ZERO) | 退出码 `136` = 128+SIGFPE(8)，无输出 |
| `INT_MIN / -1` | **运行时失败**：商溢出，进程非零退出，无输出 | `idiv` 触发 `#DE` | 退出码 `0xC0000095` (STATUS_INTEGER_OVERFLOW) | 退出码 `136` = 128+SIGFPE(8)，无输出 |
| 加/减/乘溢出 | **静默二补码回绕**（wrap），不报错、不截断异常 | `add`/`sub`/`imul` 自然回绕 | `INT_MAX + 1 = -9223372036854775808`；`INT_MAX * 2 = -2`；RUN_RC=0 | 同左，RUN_RC=0 |

> [!note] 为什么崩溃码不同
> 两边都是 x86-64 `idiv` 触发 `#DE`（除法异常），语义完全一致。差异只在 OS 如何把异常报告给进程：Windows 转成 NTSTATUS 退出码（`0xC0000094`/`0xC0000095`），Linux 以 SIGFPE 信号终止（shell 中 `$?` = 128+8 = 136）。**契约层面统一表述为"运行时失败、非零退出、无输出"**，不绑定具体数字。

## 给使用者的规则

1. **不要依赖溢出产生错误**：加减乘溢出是静默回绕，程序继续跑，结果可能错误但退出码为 0。需要溢出检测时必须显式检查边界（当前语言尚无内置溢出检查函数）。
2. **除法和取模前必须保证除数非零**：零除会让程序直接崩溃（非白泽诊断，是 CPU 异常），当前编译器不做静态零除检查。
3. **`INT_MIN / -1` 是禁区**：结果数学上是 `9223372036854775808`，超出 int64，会触发溢出崩溃。取绝对值、求相反数时要避开 `INT_MIN`。

## 与回归测试的关系

- 除法向零截断已在 `tests/cases/03_变量赋值与表达式.bz` 覆盖（`-7 / 3 = -2`）。
- 零除、`INT_MIN/-1`、加减乘溢出是**崩溃/回绕行为**，无法用常规 stdout 断言，另由 `tests/crash/` 用例通过退出码断言（见 `tests/README.md`）。
