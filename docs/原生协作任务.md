# 原生并发首个子里程碑：协作式任务

这是 x86-64 Windows/Linux 的实验接口，不是并发阶段的最终语言契约。每个任务有独立的白泽栈，在同一个 OS 线程上切换；没有并行、抢占或阻塞 I/O 集成。

| 操作 | 首版行为 |
| --- | --- |
| `启动任务(具名函数, 整数实参)` | 仅主任务可调用；入口必须是一个整数参数、返回整数的白泽函数。成功返回正整数编号；超过启动额度或从工作任务启动返回 `-1`。只入队，不立即执行。 |
| `让出任务()` | 挂起当前栈，按编号轮转至下一个可运行任务，主任务也参与。恢复后返回 `0`。没有其他任务时直接返回。 |
| `等待任务(编号)` | 主任务挂起等指定工作任务结束，再返回该函数结果；可重复读取，也可能因全体无法推进而返回 `-3`。无效编号或工作任务调用返回 `-1`。栈保护终止返回 `-2`，取消返回 `-4`；如果工作函数本身也返回这些整数，用 `任务结局` 区分。 |
| `取消任务(编号)` | 仅主任务可调用。取消尚未开始、已让出或阻塞的工作任务，成功 `0`，已经终止 `1`，非法 `-1`；不再恢复其栈。 |
| `任务结局(编号)` | 活动 `0`、正常返回 `1`、已取消 `2`、栈保护终止 `3`、无效编号 `-1`。 |
| `释放任务(编号)` | 仅主任务可调用。已结束任务释放成功 `0`；活动任务不变并返回 `-2`；无效、已释放编号或工作任务调用返回 `-1`。 |

每进程最多同时持有八个尚未释放的工作任务；结束但未释放仍占槽，保留结果供重复等待。显式释放后，旧编号对等待、查询、取消和释放都无效。新任务可使用同一物理槽，但获得不同编号；编号是不可解读的句柄，不能用来推算槽位。工作任务重用前清空根计数和通道读取槽。 每个栈预留 128 KiB，白泽发射的函数序言和表达式压值位置做限额检查，预留余量供运行时使用；不是操作系统守卫页或任意本地代码隔离。主任务退出不会替程序等待剩余工作，调用者必须显式等待。已支持有界整数通道和显式取消。取消不会关闭共享通道或撤销已产生的副作用，也不会执行被废弃栈上的用户代码；程序负责显式关闭资源。尚无外部事件或 I/O 唤醒。任务内现在可以分配、读写字节向量。主栈与各工作栈分别登记精确根；回收时扫描主任务和所有未结束的工作任务，栈保护终止后不扫描该任务的废弃栈。当前任务入口与结果仍只支持整数，不能跨任务参数直接传向量。

编译器按实际调用链接运行时，未调用任务的对照程序与上一版生成的映像字节相同。`runtime/native-tasks-x64.S` 是对应的可读汇编，编译器直接发射机器码并填入任务区地址，启动入口只用编译期确认的函数地址；运行时不调用汇编器或宿主任务框架。

## 有界整数通道

`新建整数通道(容量)` 接受 1–8，返回正整数编号；容量无效或本进程八个通道额度用尽时返回 `-1`，编号不复用。`通道发送(编号, 整数值)` 在满时挂起，`通道接收(编号)` 在空时挂起；就绪后相关等待者被唤醒并重查条件。缓冲数据按入队顺序读取，不保证等待者严格先到先服务。两者成功返回 `0`。接收后的 `通道取值()` 读取当前任务最近一次成功接收的完整有符号整数；失败会把该任务的读取槽置零，只应在接收返回 `0` 时作为业务值使用。

`关闭通道(编号)` 第一次关闭返回 `0`，唤醒等待的读者与写者，保留已入队的数据。写入已关闭通道、重复关闭、读完关闭通道之后再次读取均返回 `-2`；无效编号返回 `-1`。调度器仅在没有任何可运行任务时让一项阻塞操作返回 `-3`，优先返回给主任务，保留通道状态；调用者可主动关闭并重新等待。这不是超时或抢占检测：不主动让出、也不挂起的死循环仍能独占线程。

## 真实程序：批量源码行统计

```text
python3 -B scripts/baize.py build --compiler <本机白泽编译器> --合入 examples/源码行统计向量核心.bz examples/源码行统计协作.bz -o <目标文件>
```

使用同一核心编译 `examples/源码行统计向量.bz` 得到串行版。协作版把奇偶文件分给两个任务，先同步读入并复制到各自的向量，再分块让出；主任务按入参顺序取结果。遇到第一个按输入顺序判定的文件错误，先取消尚存的任务、确认终止、关闭通道，再报告错误。没有宣称 I/O 重叠或提速。

### 文件向量背压

把构建命令的入口替换成 `examples/源码行统计背压.bz`，得到八个常驻工作任务、最多三个文件在途的版本。主任务向容量为 3 的共享工作通道派发一组文件；闲置工作任务阻塞接收，并不轮询等额度。每组用三个容量为 1 的结果通道按输入位置收回完整有符号结果，组间不交叠。工作任务在完成文件向量的扫描并退出持有它的函数后才发送结果。

固定的 1 MiB 对象区放得下三个最大文件向量（每个含 8 字节块头）。这个上限约束的是应用的在途文件，不是所有白泽程序的通用内存策略；不增加堆、任务或通道额度。组内仍每 8 KiB 让出，保留单线程协作，文件 I/O 仍同步。如果出现文件错误，已输出的前序结果保留，主任务取消并等待其余任务后关闭通道。正常结束先关闭工作通道，等待所有工作任务返回，再关闭结果通道。

## 验证

函数序言与表达式压栈仍检查栈下界。调度器切换栈时同步更新当前下界，主任务的下界是零；快速路径内联一次比较与条件分支，只有触及下界才进入终止例程。保留原有 16 KiB 余量与终止结果，不借关闭栈保护提速。未调用任务的程序不生成这些检查。

- `python3 -B tests/check-task-stack-fast-path.py <第三代白泽编译器>`：执行堆栈限额、终止任务根清理、往返切换，并核对 PE/ELF 生成代码中快路径下界地址和共享慢路径。旧版加 `--before`，确认它保留行为但没有内联检查。
- `python3 -B tests/check-line-count-backpressure.py <第三代白泽编译器>`：对照串行版与独立结果，单进程处理 96 个真实源码输入、最大文件长度、乱序完成后按序输出、缺失及超限输入和错误收尾。
- `python3 -B tests/check-task-reuse.py <第三代白泽编译器> --baseline <旧编译器>`：覆盖已结束槽复用、旧句柄与活动释放拒绝、取消后的根和信箱清理、栈保护、1000 次无向量任务生命周期，以及 `源码行统计任务波次.bz` 的 97 项真实批处理。把上面的构建入口换成该文件即可复跑按波派发。它使用三个任务槽轮转，不替换现有常驻池。
- `python3 -B tests/check-task-cancel.py <第三代白泽编译器>`：取消待运行与已阻塞任务、幂等返回、对象区可再分配、正常负数结果与终止原因分离。
- `python3 -B tests/check-vector-line-count.py <第三代白泽编译器> --concurrent`：用官方构建命令编译两版，逐字节比较真实批次和错误退出，独立算出每个文件的正确结果。
- `python3 -B tests/check-native-channels.py <第三代白泽编译器>`：核对满空等待、完成唤醒、有符号值、关闭后排空、关闭唤醒写者、无进展返回后的关闭和重试；对旧编译器加 `--before`，验证明确拒绝且不产物。
- `python3 -B tests/check-native-tasks.py <第三代白泽编译器> --baseline <上一里程碑第三代>`：先启动两个工作，再断言主任务继续、两个工作交替、局部值在挂起后保留、返回正确；检查非法入口和参数、无效句柄、数量上限与深递归受控终止。
- `python3 -B tests/check-task-gc.py <第三代白泽编译器>`：同时保留主任务和挂起工作任务的哨兵值，由另一工作任务触发回收；另验栈保护中止后可重新申请满对象区。对旧编译器使用 `--before` 核对明确拒绝且无产物。
- `python3 -B tests/check-gc-encoding.py`：在 GNU Binutils 环境对照任务及向量运行时的发射字节、入口偏移和无重定位；不是自举依赖。
