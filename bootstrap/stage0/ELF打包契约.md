## 输入和输出

- 输入为 GNU as --64 产生的单个 ELF64 小端 x86-64 ET_REL。读取节表、符号表、符号字符串表和 RELA。
- 布置可执行 PROGBITS、只读 PROGBITS 和零填充的可写 NOBITS。GNU as 会生成空的可写 PROGBITS，允许它存在。使用全局符号 _start 设置入口。
- R_X86_64_PC32 写入有符号 32 位的 S + A - P，其中 S 为解析后的符号地址，A 为带符号加数，P 为待回填字段地址。R_X86_64_64 写入 64 位的 S + A。基线目标文件分别有 62 个和 4 个，数量会随源码变化。
- 输出为固定地址静态 ET_EXEC。代码和只读数据、可写零填充数据各有明确的段权限，栈无需执行权限。输入超限、越界、未定义符号和未知重定位须失败。

## 验收

运行 bash scripts/check-stage0-no-ld.sh 已有白泽编译器。脚本先用 GNU as 生成种子和对照目标文件，然后隔离构建工具。已有白泽编译器在空 PATH 下构建 ELF打包器.bz，打包器也在空 PATH 下运行。脚本验证重复打包的确定性、两种重定位、非零入口地址偏移、BSS 清零、段权限、截断输入、未知重定位、未定义符号和相对位移溢出。最后以白泽打包的种子生成白泽编译器并复跑三代原生自举。

CI 从同一次运行的 GNU 冷启动作业获得既有宿主，核验归档哈希后才启动替代路径。该宿主是本阶段的可信输入。替代路径自身无需调用 ld，仍用 GNU as 生成目标文件。CI 比较两条路径生成的首个白泽编译器及固定点 ELF，并分别归档产物。
