# 白泽 Stage 0 汇编器子集

本次盘点以 dev 提交 f080fcc 的 bootstrap/stage0/seed.s 为准。输入是 GNU Intel 记法的原始种子源码。白泽汇编器分两遍处理文本，第一遍记录符号和节内偏移，第二遍生成机器码和重定位，最后交现有白泽 ELF 打包器处理 ET_REL。

## 指令和操作数

| 用途 | 种子实际使用 |
| --- | --- |
| 数据移动 | mov、movzx、lea、push、pop |
| 算术和逻辑 | add、sub、cmp、test、xor、or、inc、dec、neg、not、shl、imul、div |
| 跳转和调用 | jmp、call、ret、ja、jae、jb、jbe、jc、je、jl、jle、jnc、jne、jns、jnz、jo、js、jz |
| 字符串指令 | rep movsb、repe cmpsb |
| 标志和系统调用 | cld、stc、syscall |

操作数覆盖种子所用的低字节、16 位、32 位和 64 位通用寄存器、立即数、标签、RIP 相对地址，以及基址、索引、倍数和位移组成的内存地址。支持 byte、word、dword、qword ptr 和 OFFSET FLAT 写法。字面量包括十进制、十六进制和单引号字符。标签表达式支持加减、非负常数乘积、同节地址差和当前节位置。分支和普通内存位移使用固定宽度，省去分支松弛处理。

## 指示和 ELF

- 支持 .intel_syntax noprefix、.global _start、.equ、.section、.ascii、.asciz、.balign、.byte、.short、.long、.quad、.zero、.lcomm。
- 布置 .text、.rodata 和 .bss。输入的 GNU-stack 标记映射到打包器生成的不可执行栈。输出节符号和 _start，重定位使用 R_X86_64_PC32 与 R_X86_64_64。
- 源码上限 262144 字节，符号及重定位各最多 1024 项。常规指令和数据发射当前节内必须符合种子使用的形式。越界立即数、未定义或重复符号、超范围分支和未知指令会返回非零，语法失败时不创建目标文件。

## 验收

运行 bash scripts/check-stage0-no-binutils.sh 已有白泽编译器。脚本先隔离 PATH，再由已有白泽编译器编译汇编器和打包器，两者随后直接处理原始 seed.s。验收检查重复汇编与打包是否逐字节一致、修改指令是否改变产物和程序退出码、非法输入是否被拒绝，并运行扫描样例和三代原生自举。

CI 从同一次 GNU 基线作业取得已有白泽编译器作为可信输入。白泽汇编和打包路径自身无需 GNU as、ld、Rust 或 C 编译器。固定宽度编码与 GNU 的指令选择不同，种子和首个编译器的文件字节可以不同。后续三代必须收敛到与 GNU 路径完全相同的 ELF。CI 独立归档目标文件、种子、各代编译器、哈希和日志。
