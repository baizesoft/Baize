# Linux x86-64 独立冷启动

## 可信起点

trust-root/seed.hex 是 12931 字节静态 ELF 的纯文本十六进制表示。它来自 dev 提交 71040e2 的 P2 CI 运行 44671227173，归档为 baize-assembler-linux-x86-64，文件名为 seed。下载归档后重新计算并核对了摘要。源码入口是 bootstrap/stage0/seed.s，同一提交提供汇编器和 ELF 打包器源码。

GNU 基线哈希来自同次运行的 assembly-cold-start-linux-x86-64 归档。本地重新计算了两条 P2 路径的 stage3 哈希并确认一致。提交内的两个清单分别约束起点和最终产物。种子二进制、源码、Bash、Linux x86-64 宿主和校验工具属于信任边界。重复构建证明当前链条能复现已记录的字节。机器码的独立审计仍以所列源码、历史参考路径和本机反汇编为依据。

## 复验

在 Linux x86-64 从仓库根目录运行 bash scripts/check-stage0-trust-root.sh。

1. 先限制 PATH，再用 Bash 内建操作把十六进制还原成 ELF。验证哈希后，才在空 PATH 下执行种子。
2. 种子直接编译现有白泽编译器。生成的编译器再构建白泽汇编器和 ELF 打包器。
3. 这两个白泽工具重新处理原始 seed.s，生成目标文件和种子。把重建的种子与可信输入逐字节比较。
4. 从重建的种子再次编译白泽编译器，跑三代原生自举、扫描样例和完整验收，最后核对 GNU 参考路径的固定点哈希。

Independent trust-root bootstrap 工作流独立检出源码。它不下载任何历史构建产物，也不依赖同一次运行中的 GNU 基线作业。证据归档包含实际启动的种子、重建的种子、首个白泽编译器、汇编器、打包器、目标文件、三代 ELF、哈希和日志。

## 更新可信根

只有有意改变种子字节或固定点时才更新清单。先用参考路径和白泽路径复跑并交叉比对，保存来源提交、CI 运行、对应源码哈希和工具产物。再更新 seed.hex 与对应清单，检查独立作业能从新的种子复现同一字节。保留旧版本的记录以便复核。
